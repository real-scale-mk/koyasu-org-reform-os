# Pane1 — 現象とA00

> **ステータス:** grill-me 確定（2026-06）

## 役割

案件の**入口**。現場で観察された現象の**収集・選択**を主目的とする。

- Pane1 = 現象収集
- Pane2 以降 = 分析を深める

採用ひな形の「候補者一覧」に相当する。選択中の現象が Pane2〜4 の連携軸になる。

---

## 用語（確定）

| 用語 | 粒度 | 説明 | 画面上のラベル |
|------|------|------|----------------|
| **案件A00** | 案件1件 | 案件全体の北極星 | 「案件A00」 |
| **目指す姿** | 現象1件 | その現象が解消されたときの具体状態 | 「目指す姿 / Target State」 |

**注意:** 「A00」という言葉は**案件A00のみ**に使う。現象ごとのものは A00 と呼ばない。

---

## レイアウト（確定）

```
┌─ Pane1 ─────────────────────┐
│ 【案件A00】北極星カード      │  ← 常時表示・編集可
│ 例：自律的に改善が回る…      │
├─────────────────────────────┤
│ 現象リスト                   │
│ ▶ 若手離職                   │  ← 1件のみ選択
│   他人事文化                 │
│   技術伝承不足               │
│   不具合頻発                 │
│   ＋ 現象を追加              │
├─────────────────────────────┤
│ 【選択中の現象】詳細パネル    │  ← リスト下固定
│ 目指す姿  [textarea]         │
│ 重要度    [Select]           │
│ 状態      [Select]           │
│ メモ      [textarea]         │
└─────────────────────────────┘
```

- 案件A00 は現象リストと**縦に並べ**、ギャップとして読める位置に置く
- Pane2〜4 に遷移しても Pane1 の案件A00 が見える構成を維持する
- 未選択時：詳細パネルは「現象を選択してください」

---

## データ項目

### 案件（cases）

| 項目 | 型 | MVP |
|------|-----|-----|
| case_name | string | 表示のみ（例：A社 — 組織改革） |
| case_a00 | string | 編集・保存 |
| selected_phenomenon_id | string | 選択連動・保存 |

### 現象（phenomena）

| 項目 | 型 | MVP |
|------|-----|-----|
| id | string | 自動採番 |
| label | string | 追加時必須 |
| target_state | string | 目指す姿（自由記述） |
| importance | enum | 高 / 中 / 低 |
| status | enum | 未着手 / 分析中 / 介入中 / 完了 |
| memo | string | 自由記述 |

**将来拡張:** 重要度の数値化、状態の細分化（検証中・保留 等）

---

## 操作範囲（MVP）

| 操作 | MVP | 後フェーズ |
|------|-----|-----------|
| 現象の選択 | ○ | — |
| 案件A00 の編集 | ○ | — |
| 目指す姿 / 重要度 / 状態 / メモの編集 | ○ | — |
| 現象の追加 | ○（現象名のみ） | — |
| 現象の削除 | × | ○ |
| 現象のアーカイブ | × | ○ |

### 現象追加フロー

1. 「＋ 現象を追加」→ ダイアログで**現象名のみ**入力
2. 初期値：重要度=中、状態=未着手、目指す姿/メモ=空
3. 追加直後に**自動選択** → 詳細パネルで追記

## デモ seed（確定）

**案件**

- 案件名：`A社 — 組織改革`
- 案件A00：`自律的に改善が回り、技術と人が継承される製造現場`

**現象4件（seed 固定）**

| 現象名 | 重要度 | 状態 | 目指す姿（初期値・編集可） |
|--------|--------|------|---------------------------|
| 若手離職 | 高 | 分析中 | 3年定着率が業界平均以上 |
| 他人事文化 | 高 | 未着手 | 部門横断で問題を共有できる |
| 技術伝承不足 | 中 | 未着手 | ベテラン知見が若手に渡る |
| 不具合頻発 | 中 | 未着手 | 再発防止が現場で回る |

**初期選択:** `若手離職`（起動直後から Pane2〜4 が連動表示）

**種別タグ:** MVP では設けない（現象名で十分）。追加現象（例：責任曖昧化）はユーザーが追加する。

## 保存（MVP → Neon）

### MVP（確定）

- **方式:** 編集後 **debounce 自動保存** → **localStorage**
- **目的:** リロードしても消えないことを最小構成で確認
- **保存対象:**
  - 案件A00
  - selected_phenomenon_id
  - 全現象（seed + ユーザー追加分）：label, target_state, importance, status, memo

### 第2フェーズ

- 同じ保存対象を **Neon API** に差し替え
- DB テーブル：`cases` / `phenomena`（[data-boundary.md](../data-boundary.md) 参照）

---

## Pane2〜4 連動

- **単一選択:** 常に1現象のみ選択
- **連動:** `selected_phenomenon_id` 変更 → Pane2/3/4 が選択現象に応じて更新
- GlobalHeader：案件名 + 選択中現象名を表示

---

## 載せないもの（Pane1 外）

- 構造仮説の詳細 → Pane2
- レバレッジ・打ち手 → Pane3
- 実行成果・SKILL化 → Pane4
