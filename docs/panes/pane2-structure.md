# Pane2 — 構造分析

> **ステータス:** grill-me 確定（2026-06）

## 役割

**なぜ現象が続くか**を、人・制度・関係性の観点から分析するペイン。

- Pane1 = 現象収集・選択
- **Pane2 = 分析を深める（構造）**
- Pane3 = レバレッジと打ち手

採用ひな形の「候補者詳細」に相当する。Pane1 で選択中の現象に連動する。

---

## MVP スコープ（確定）

今回の MVP は **分析観点カード ＋ 詳細 Sheet** まで。

| 含む | 含まない（後フェーズ） |
|------|------------------------|
| 7観点カード一覧 | 因果関係図 |
| 関連度バッジ + ソート | 構造図フル画面 |
| 「詳細を見る」Sheet | 構造分析メモ・仮説の保存 |
| 選択現象に応じた強調 | Neon 保存 |

**将来:** Pane2 は **因果関係図・構造図** へ発展予定。「構造図を見る」等の拡張入口を UI に残す余地あり（MVP ではダミー or 未実装可）。

## 分析観点（7つ・固定）

| ID | 観点名 | 1行サマリー（seed 用・TBD） |
|----|--------|---------------------------|
| `people` | 人・関係性 | 部門間の連携と信頼 |
| `accountability` | 責任の曖昧さ | 誰が決め・誰が動くか |
| `meetings` | 会議構造 | 決裁と持ち帰りのパターン |
| `evaluation` | 評価制度 | 育成・挑戦が評価に反映されるか |
| `tech-transfer` | 技術伝承 | ベテラン知見の継承 |
| `psych-safety` | 心理的安全性 | 本音と対立を扱えるか |
| `manager-behavior` | 管理職行動 | 現場リーダーの関与 |

詳細な型・問いの型は [methodology/](../methodology/) に置く（Git/Markdown）。

## Pane1 連動（確定）

### 関連度

- 現象ごとに **seed 固定**（MVP では編集不可）
- 3段階：**高 / 中 / 低**
  - **高** = 主因候補（強調表示）
  - **中** = 関与あり
  - **低** = 今回スコープ外（opacity 下げて残す）

### 表示ルール

1. 選択現象に応じて `relevanceByPhenomenonId` を参照
2. カードを **関連度 高 → 中 → 低** の順にソート
3. ヘッダーに選択中現象名を表示

### デモ seed：若手離職（初期選択）

| 観点 | 関連度 |
|------|--------|
| 責任の曖昧さ | 高 |
| 会議構造 | 高 |
| 管理職行動 | 高 |
| 評価制度 | 中 |
| 心理的安全性 | 中 |
| 人・関係性 | 低 |
| 技術伝承 | 低 |

他現象（他人事文化 / 技術伝承不足 / 不具合頻発）の関連マップは **最小プレースホルダ**（[data-boundary.md](../data-boundary.md) §4現象 seed 方針）。若手離職のみフル seed。

## 「詳細を見る」Sheet（確定）

- **UI:** shadcn `Sheet`（右からスライド）
- **構成（3部）:**
  1. **見方** — なぜこの観点が重要か（2〜3行、methodology から）
  2. **確認する問い** — 3〜5個のチェック用問い
  3. **選択現象での例** — 選択中現象に応じた1段落（seed 差し替え）

MVP: 全文静的（JSON seed）。編集・保存なし。

**方針:** MVP の保存対象は **Pane1 + Pane4**（[data-boundary.md](../data-boundary.md) 参照）。Pane2 は完全静的。
